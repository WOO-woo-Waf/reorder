# 星绫解封 · Hoshiribbon 桌面版用户指南（Windows）

本指南面向两类人：拿到安装包或便携包后要实际操作 Windows 桌面版的用户，以及负责最终验收这些操作的验收人。它讲清楚文件怎么放、界面每个按钮做什么、结果落在哪里，以及用真实文件验收时应该看到什么。

相关文档：产品范围见 [product_plan.md](product_plan.md)，工程设计见 [desktop-design.md](desktop-design.md)，实施进度与检查证据见 [desktop-status.md](desktop-status.md)。旧的命令行便携版见 [portable_user_guide.md](portable_user_guide.md)，那是另一个入口，不要与本桌面版混用。

## 0. 交付范围与验收边界

本指南对应 Windows x64 桌面版 **0.3.1**（本地待确认）。**0.3.1 尚未发布**，本轮不新增 Release 链接；当前对外仍是 0.3.0 预发布。当前构建是否成功、Git 提交和检查记录统一见 [desktop-status.md](desktop-status.md)；本指南介绍运行方法。真实文件、操作体验与干净机器安装仍由用户按第 12 节人工验收。

| 项目 | 交付入口 | 说明 |
| --- | --- | --- |
| 桌面源码 | `apps/desktop`、`src/reorder_engine` | 已批准技术栈；保留 CLI |
| Python 冻结引擎 | `engine/reorder-engine.exe` | 必须保留完整 `_internal` 与工具目录 |
| 桌面 EXE | `Hoshiribbon.exe` | 使用系统 WebView2 |
| NSIS 安装包 | `Hoshiribbon_0.3.1_x64-setup.exe` | 用户级安装，尚未签名（该文件名对应本地待确认的 0.3.1 构建） |
| 便携 ZIP | `Hoshiribbon-0.3.1-windows-x64.zip` | 解压整个目录；完整性看 `SHA256SUMS.txt` |
| 真实窗口、文件、安装卸载 | 用户人工验收 | 合成引擎检查和源码检查不能替代这一项 |

已发布的 **0.3.0** 文件名（历史记录，下载链接仍有效）：`Hoshiribbon_0.3.0_x64-setup.exe`、`Hoshiribbon-0.3.0-windows-x64.zip`。

请按本指南第 12 节用**副本样本**开始人工验收；不要把实现完成等同于真实业务验收通过。

## 1. 系统要求

- Windows 10 或 Windows 11，**x64**。当前只配置了 x64 目标。
- **WebView2 Runtime**（界面渲染依赖它，见下）。
- 足够磁盘空间：处理时会先在内部工作区准备副本，再发布成品并归档原件。单包大概需要“原件总大小 × 2 以上”的临时空间，另外还要留出成品空间。
- 你**不需要**自己安装 Python、Node.js、Rust、7-Zip 或 WinRAR。界面、Python 引擎、7-Zip 25.01、UnRAR 7.13 和 Bandizip CLI 7.40.0.1 都随包提供。Bandizip 已按所有者的书面分发许可声明纳入固定依赖。

### 关于 WebView2

桌面界面用系统自带的 WebView2 渲染，这是 Windows 上的运行时组件：

- Windows 11 已经把 Evergreen WebView2 Runtime 作为操作系统的一部分内置。
- Windows 10 上它**不一定**已经安装：很多装有 WebView2 应用（例如新版 Edge/Office）的机器会有，但没有的机器需要补上。
- 本项目当前的 Tauri 配置没有显式设置 `webviewInstallMode`，因此走 Tauri v2 的默认值：NSIS 安装包在运行时会**联网下载并静默安装** WebView2 引导程序；便携 ZIP **不携带** WebView2。所以离线安装、或目标机器没有 Evergreen Runtime 时，需要你提前装好运行时。

如果不确定机器上有没有，可以打开“设置 → 应用 → 已安装的应用”，查找 “Microsoft Edge WebView2 Runtime”。参考链接见第 14 节。

## 2. 你会拿到什么（产物形态与文件树）

发行产物有两种形态；拿到后按下列结构核对完整目录。

### 2.1 便携包（ZIP 解压即用）

解压后目录（由 `scripts\build_desktop_windows.ps1` 生成到 `artifacts\desktop\Hoshiribbon-portable\`，再压成 `Hoshiribbon-0.3.1-windows-x64.zip`）：

```text
Hoshiribbon-portable\
  Hoshiribbon.exe              # 桌面主程序，双击运行
  Start-Portable.cmd       # 显式便携模式：数据在旁边 data/，公开密码文件也在那里持久保存
  README.txt
  package-manifest.json    # 包内文件大小和 SHA-256
  docs\                    # 用户、代码、语言、设计指南及图表
  licenses\                # 第三方许可文本与证据清单
  engine\                  # Python 业务引擎，必须与 Hoshiribbon.exe 一起保留
    reorder-engine.exe
    _internal\             # 引擎运行时依赖
    tools\
      7zip\                # 随包 7-Zip（含 License.txt）
        ...
      unrar/               # 固定 UnRAR 与许可
      bandizip/            # 固定 bz.exe、Ark DLL 与公开许可
      apate.py
    defaults/              # 内置公开词库与固定身份清单
```

注意：

- **不要只把 `Hoshiribbon.exe` 拷走单独运行**。必须保留整个 `engine\` 目录，里面是处理压缩包所需的真实引擎和 7-Zip。
- 双击 `Hoshiribbon.exe` 使用默认用户数据目录；双击 `Start-Portable.cmd`（等价于 `Hoshiribbon.exe --portable`）使用 EXE 旁的 `data\`，该目录必须可写，公开密码文件也持久保存在那里的 `data\passwords.txt`。两者都需要系统 WebView2。
- 包内指南和图表可直接阅读；制作方指南中的源码链接需要在完整 Git 仓库内打开。

### 2.2 安装包（NSIS）

由 `npm run tauri build` 生成，位置：

```text
apps\desktop\src-tauri\target\release\bundle\nsis\Hoshiribbon_0.3.1_x64-setup.exe
```

- 安装模式为 `currentUser`（当前用户安装，不需要管理员）。
- 安装语言可选简体中文 / English。
- 安装包会把引擎资源安装到程序资源目录；如果机器缺少 WebView2，安装过程会尝试联网获取运行时。

## 3. 启动与界面总览

双击 `Hoshiribbon.exe`、`Start-Portable.cmd`，或从开始菜单启动安装版。窗口标题是“星绫解封 · Hoshiribbon”，最小尺寸 860×620。

界面从上到下是：

1. 顶部标题栏：产品名、副标题“把压缩的次元，一层层展开。”，右侧“设置”按钮（未就绪或任务进行中时不可点）。
2. 概览卡片：待处理文件组数量、处理模式（“深度解压”或“单层解压”，由设置决定）、原包归档提示“校验后移动”。
3. **01 添加文件**：拖放区、添加按钮、工作文件夹。
4. **02 确认并处理 / 处理结果**：扫描/开始/取消/重试按钮、进度条、文件组状态表、处理记录。
5. 最近任务：本机保存的历史列表。
6. 底部状态栏：平台与版本（如 `Windows · v0.3.1`）、7-Zip 是否就绪、当前密码条数。

> 界面所有处理都在本机完成，不联网处理你的文件。唯一可能的联网动作，是安装包在缺少 WebView2 时下载运行时组件。

## 4. 主流程：添加 → 扫描 → 开始 → 取消

### 4.1 添加文件（01 添加文件）

三种方式：

- 点“添加文件”，在系统对话框里多选文件。
- 点“添加文件夹”，选择一个目录（是否包含子目录由设置里的“扫描输入的子目录”决定）。
- 直接把文件或文件夹**拖进窗口**。

规则：

- 请你先只用**副本样本**：把要试的文件复制一份到专门的试验目录，输入指向副本，不要第一次就指向唯一的原始资料（见第 11 节）。
- 明确选中文件时，只处理你所选文件组成的完整分卷组，不动旁边的文件；选中目录时会扫描目录内容。
- 已添加的条目可以“移除”。
- 若首次引擎初始化失败，可点击“刷新任务”重试；成功后扫描和设置恢复可用。引擎异常退出后刷新只恢复状态记录，不会自动重新处理原件。
- 输入和输出路径都不接受符号链接/连接点（Windows 上的 junction 也会被拒绝）。

**工作文件夹**：点“选择”指定成品、原包与临时工作的落点。要求：

- 必须是绝对路径的目录。
- 不能落在软件安装目录或软件内部数据目录里。
- 与输入目录相互独立会更安全，便于你事后区分。
- 可以选一个**已有内容**的文件夹：软件会复用已存在的同名目录，但从不覆盖已有文件，冲突项安全改名或隔离到 `_duplicates`，也不会清理你原有的内容。
- 选择会被记住：写入设置，重启后自动恢复上次的工作文件夹。

界面提示：“所选工作文件夹容纳全部产物：成品写入 `final`，成功原包归档到 `success`，失败或缺卷的文件进入 `error`，中间结果和临时工作区也在这里。会复用已存在的同名目录，不会覆盖已有文件。”

### 4.2 扫描（只读预览）

添加好输入并选好工作文件夹后，点“扫描”。这一步是**只读的**：

- 引擎按“文件组”识别分卷、伪装后缀、合并文件（PDF/图片/媒体前缀 + 尾部压缩包）等，给出分组预览：每个文件组的名称、成员数、总大小。
- 扫描不会移动、不会改写你的文件。
- 可能出现警告文字，例如“已扫描子目录；原件按文件组归档，不会预先展平输入”“处理完成后原包会移动到输出目录的归档或错误分类，处理前不会改写原件”。
- 若扫描后你改了输入、输出或设置，需要重新扫描。

### 4.3 开始处理

确认分组后点“开始处理”。过程分几个阶段，界面状态会依次显示：准备副本 → 恢复 / 解压 → 发布成品 → 归档原包。

每个包的底层顺序是：复核原件 → 在工作文件夹的临时工作区准备副本 → 在工作副本上恢复/解压 → 校验后发布成品 → 校验复制结果后删除原件并把原件路由到归档或分类目录。**原件不会原地改写**，但它会在成功后被移动到工作文件夹（这点很重要，先用副本试）。

### 4.4 取消与关闭窗口

- 任务进行中点“取消”，按钮变为“正在取消”。取消是在**安全边界**生效：当前正在提交的那一步会做完，避免留下半删的原件；尚未开始的包标记为“已取消”，原件留在原处。
- 任务进行中直接关窗口，会弹出确认：“任务仍在处理。取消后请等待文件安全收尾，再关闭软件。”可选择“取消任务”或“继续处理”。
- 退出软件时，宿主会让引擎先收尾当前文件提交；超时后用进程树终止兜底。

## 5. 结果与分类

处理完成后，**工作文件夹**下会按类别出现以下目录（取决于每个包的结果）：

| 目录 | 含义 |
| --- | --- |
| `final\` | 完全成功或部分成功时解出/恢复出的成品，优先看这里 |
| `success\archives\` | 成功处理后的原始压缩包（原件归档位） |
| `error_files\<类别>\` | 失败原件，按失败类别分目录 |
| `deferred_volumes\<文件组>\` | 缺少分卷、暂缓处理的文件组 |
| `_duplicates\` | 同名冲突时的隔离目录，防止覆盖已有文件 |
| `intermediate\` | 本次运行的临时工作区（副本、恢复与解压中间结果，及解压工具的 TEMP/TMP/TMPDIR）；开启“保留临时工作区”才留在盘上 |

这些目录直接位于所选工作文件夹根下；临时工作区在其 `intermediate\workspaces\<作业>\<文件组>\` 内（该次运行目录已被占用时会用唯一同级目录，不动你原有的内容）。软件从不覆盖已有文件，所以工作文件夹可以放心指向一个已经装有别的内容的目录。

`error_files\` 下的类别名：

- `password_error`：密码不对或加密无法解开。
- `unknown_type`：引擎无法识别类型。
- `missing_volume`：缺分卷。
- `extract_failed`：其它解压失败。

文件组状态的含义（界面里会显示这些中文名）：

| 状态 | 界面文字 | 含义 |
| --- | --- | --- |
| `succeeded` | 完成 | 全部成功 |
| `partial` | 部分完成 | 有成品，但存在缺卷等未完成部分 |
| `failed` | 失败 | 该组处理失败 |
| `deferred` | 等待补卷 | 缺分卷，暂缓，原件放到 `deferred_volumes` |
| `cancelled` | 已取消 | 因取消未处理，原件保留 |
| `interrupted` | 已中断 | 引擎异常退出导致中断 |
| `needs_review` | 需要检查 | 发布或归档无法确定是否完成，需要人工核对，**不会自动重跑** |

结果表里“说明”列会给出错误码或简短说明。0.3.1 起公开密码按公开数据处理，**日志不再掩码密码**；私人密码请勿写入密码文件。

## 6. 打开工作文件夹

任务卡片右上角“打开工作文件夹”会调用系统文件管理器打开已登记的路径。出于安全，它只允许打开**引擎登记过**的结果路径，不会打开任意路径。

## 7. 重试

任务结束后，“开始处理”位置会换成“重试 (N)”，N 是可重试的文件组数量。

- 可重试的状态：失败、等待补卷、已取消、已中断。
- 已完成或“需要检查”的包**不会**被重做；“需要检查”的包请你先人工核对后再决定。
- 重试会创建一个新任务，并保留与旧任务的关联；旧的成功包不会重跑。
- 已经路由到错误分类的原件，会被当作重试输入读回。

## 8. 最近任务（历史）

- 历史保存在本机 SQLite（默认 `%LOCALAPPDATA%\io.reorder.desktop\jobs.sqlite3`；显式便携模式为 EXE 旁 `data\jobs.sqlite3`），列出最近 20 条任务及状态。
- 点某条历史会载入该任务的快照与结果表；进行中的任务进行时不能切换查看。
- “刷新”重新读取列表。

## 9. 设置

点右上角“设置”。设置保存在本机，修改后需要重新扫描文件才生效。

### 9.1 处理选项

| 选项 | 默认 | 说明 |
| --- | --- | --- |
| 继续解开嵌套压缩包（深度解压） | 开 | 关闭时只解一层 |
| 扫描输入的子目录 | 关 | 开启后递归扫描输入的目录 |
| 保留内容原名 | 开 | 开：成品用内容自带的最外层目录名（保留旧引擎的名称与目录整理，最深层单层包装目录会被压缩掉）；关：改用压缩包基础名 |
| 保留临时工作区 | 关 | 开启后不自动删除中间工作目录，便于排错 |
| 最大解压层数 | 4 | 1–20 |
| 输出空间上限 (GB) | 64 | 成品空间上限 |
| 工具超时 (秒) | 3600 | 单次外部工具调用上限，1–86400 |
| 嵌套归档识别下限 (MB) | 100 | 小于该大小的文件不当作内层归档去深挖 |
| 单文件成品阈值 (MB) | 200 | 单个大文件达到该大小也视为成品，停止深挖 |

深挖的停止规则（保留旧引擎行为，细则见 [格式指南第 9 节](desktop-format-support.md)）：目录里出现 ≥10 个子目录或 ≥80 个文件即判为成品停止；唯一非媒体文件是归档、或达到 `max(识别下限, 单文件阈值)` 时才继续解一层；默认最多 4 层。深度解压在桌面版**默认开启**（旧 CLI 默认关闭），你可以关闭只解一层。

### 9.2 解压工具

- **7-Zip（必需）**：默认自动查找。便携包会自带 7-Zip；如果没找到，界面底部会提示“在设置中检查 7-Zip”。可用“选择”手动指定本机的 `7z.exe` / `7zz`。
- **UnRAR（备用，自带）**：路径留空即可自动使用随包的固定 7.13 版本，无需安装 WinRAR。
- **Bandizip（备用，自带）**：路径留空即可使用固定 CLI 7.40.0.1；`bz.exe` 与两个 Ark DLL 一起提供，也可指定本机版本。

### 9.3 公开密码文件（明文）

密码用于解开加密压缩包。0.3.1 起只有一个**可编辑的明文文件**，首次运行在数据目录生成 `passwords.txt` 并写入随包的 **115 条公开密码**；之后这个文件就是唯一来源，可查看、添加、编辑、删除或清空。

设置里的“密码集”区域：

- 多行框直接显示并编辑当前密码，每行一个条目。
- “保存密码列表”：用多行框的完整内容**整体替换**文件。
- “从文件追加”：选择一个 UTF-8 编码的 `.txt`（不超过 512 KiB），把里面的条目**追加**到现有列表。
- “重新载入”：从文件重新读取；有未保存编辑时按钮暂时禁用，先保存后再重新载入（适合你在外部编辑器里改过文件）。
- 多行框清空后保存，即删除全部密码。

格式与边界的精确规则：

- 每行一个密码，UTF-8 文本，空行忽略。
- **重复、空格和 `#` 都按字面内容保留**：不去重，也不把 `#` 当注释。
- 单条最多 4096 字符、最多 10000 条、文件不超过 512 KiB；超限会报错且不替换原文件。
- 文件必须是无链接的普通文件，保存用原子替换，失败时原文件不变。

这些归档密码是公开数据：文件以明文保存，不使用系统凭据后端，日志与错误也保留原文。

若外部编辑导致编码错误或文件超限，应用保留原文件并显示提示，设置仍可打开。先把文件修复为 UTF-8，或在编辑框填好内容后主动保存替换；此时空白编辑框不表示原文件已经清空。运行中误删整个文件也可通过保存密码列表重建；清空词库应保存空列表，不要删除文件。

手动核对步骤（拿一份副本、不要用唯一的原始资料）：

1. 打开设置，在密码集多行框末尾加一行 `smoke-test-password`，点“保存密码列表”，确认底部条数比之前多 1。
2. 用文本编辑器打开设置里显示的 `passwords.txt` 路径，确认刚加的那行在文件里；重复、空格、`#` 行都原样保留。
3. 直接关闭设置再重新打开，确认列表内容与文件一致（外部改动会重新读取）。
4. 清空多行框并保存，确认条数变 0；关闭软件再重开，确认仍是 0——**清空并重启不会补回出厂默认**。
5. 如果要恢复公开默认值，用“从文件追加”导入一份自己的 UTF-8 文本（会把条目追加回来），而不是期待软件自动重置。

### 9.4 内置关键词（不再有内置密码开关）

随包词库来自 Git 的 `resources/keywords.txt`（8 条），构建按固定 hash 校验。公开密码只负责上面那个文件的**首次播种**，没有“使用内置密码库”开关，也不再区分“私人库 / 内置库”两套来源。升级后不读取旧系统凭据库；旧 `use_builtin_passwords` 设置和 `--session-secrets` 参数只保留兼容格式，不再控制公开词库。用户维护的 `passwords.txt` 是唯一来源。

“清理成品顶层名称中的关键词”默认关闭。开启后只清理 `final` 下发布项的顶层名称，保留扩展名与包内层级，不改原件和归档名；重名安全分配，清理后无有效名称则保留原名。

### 9.5 背景与外观

设置内可选默认星夜少女、自己的 PNG/JPEG/WebP（不超过 2 MiB）或无背景；调节遮罩、模糊并保存外观。外观仅保存在当前 WebView 的本地存储，存储受限时会提示错误。恢复默认不改变密码和处理选项。图片来源与完整人工核对步骤见 [视觉说明](desktop-artwork.md)。

## 10. 用户数据与状态位置

Windows 上用户数据根目录是：

```text
%LOCALAPPDATA%\io.reorder.desktop\
```

其中：

| 路径 | 内容 |
| --- | --- |
| `settings.json` | 你保存的设置 |
| `passwords.txt` | 公开密码的明文文件（首次运行播种 115 条，之后由你维护） |
| `jobs.sqlite3` | 任务/文件组/事件/动作日志（历史） |
| `work\` | **旧版遗留**：0.3.1 起不再写入；里面可能还有旧任务留下的工作副本，仅供人工恢复核对 |
| `logs\` | 每个任务的日志（单任务约 2 MiB 滚动；0.3.1 起公开密码不掩码） |
| `engine-diagnostics.log` | 引擎诊断输出（约 2 MiB 滚动） |
| `engine.lock` | 单实例锁 |

0.3.1 起，数据目录只留这些**小型状态**（设置、密码、任务库、日志）；大型的归档工作区、成品与临时副本都放在你选择的**工作文件夹**里，不再堆在数据目录。便携模式的数据目录是 EXE 旁的 `data\`，规则相同，公开密码文件也在那里持久保存。软件安装目录里不放用户数据；工作文件夹与用户数据目录相互独立。

## 11. 只用副本样本开始（入门演练）

第一次上手请按这个顺序，全程只碰副本：

1. 新建一个试验目录，例如 `D:\reorder-trial\input`，把**要试的压缩包的副本**放进去（几个分卷要放齐，并保持原始文件名）。
2. 新建工作文件夹 `D:\reorder-trial\output`。
3. 打开软件，添加输入（拖入或“添加文件夹”），把工作文件夹设为 output。
4. 点“扫描”，确认文件组数量、名称、成员数和大小符合预期。
5. 点“开始处理”，观察状态从“准备副本”走到“完成”。
6. 处理结束后核对：output 下的 `final\` 是否有内容、`success\archives\` 是否是被移动过来的原件；中间工作区应在 `intermediate\` 内。
7. 确认无误后，再考虑用真实文件。

## 13. 常见问题

- **启动时报引擎资源缺失**：便携包没解压完整，或 `engine\` 目录被移动。保留整个目录重试。
- **界面打不开或白屏**：多半是 WebView2 缺失。安装 Evergreen WebView2 Runtime 后重试。
- **底部提示“在设置中检查 7-Zip”**：设置里指定 7z 路径，或用便携包自带 7-Zip。
- **输入或输出被拒绝**：路径含符号链接/连接点、不是绝对路径、或落在安装目录/数据目录内。
- **扫描后提示设置已改变**：改动设置后需要重新扫描。
- **组显示“需要检查”**：发布或归档无法确定是否完成，请人工核对工作文件夹与动作日志，不会自动重跑。
- **同名文件被挪进 `_duplicates`**：软件不覆盖已有文件，把冲突项隔离到那里。
- **密码文件是明文**：这是刻意的设计——公开密码不加密、不做掩码，方便直接查看和编辑；请勿把私人密码写进去，也不要把它当作机密文件。
- **数据目录里的 `work\` 还有东西**：那是旧版遗留的工作副本，0.3.1 起不再写入；需要时人工核对或自行清理，软件不会自动删除。

## 15. 附：Windows 构建命令（构建者用）

下面的入口面向制作方，需要 Windows Node、Python、Rust/MSVC。完整流程先冻结引擎、收集许可，再构建 Tauri 与包；实际执行记录见实施状态。

- 依赖环境：Windows 上已有独立 build venv（`runtime\desktop-build-venv`）、项目自带的 isolated Rust 工具链（`runtime\toolchains\cargo`）、系统 Node 与 MSVC BuildTools。
- 冻结 Python 引擎：

  ```powershell
  D:\buff\reorder\runtime\desktop-build-venv\Scripts\python.exe .\scripts\stage_desktop_engine.py
  ```

- Rust 检查 / release 编译（本项目封装，已设置代理、CARGO/RUSTUP 与 MSVC 环境）：

  ```cmd
  runtime\check-desktop.cmd
  runtime\release-desktop.cmd
  ```

  注意：`release-desktop.cmd` 这一轮是被主动中止的，日志 `artifacts\desktop\rust-release.log` 只有开始的两行，既不是成功也不是编译失败。

- 完整构建（先冻结引擎、再 `npm ci`、`npm run check`、`npm run tauri build`，最后生成本地便携目录与 ZIP；带 `-PortableOnly` 时跳过安装包）：

  ```powershell
  powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\build_desktop_windows.ps1 -Python 'D:\anaconda\python.exe'
  ```

  该脚本会把本指南 `docs\desktop-user-guide.md` 复制进便携目录，所以打包前必须先有本文件。
- 第三方许可证据收集（只读源清单，写到 `artifacts\desktop\license-evidence\`）：

  ```powershell
  python .\scripts\collect_desktop_licenses.py
  ```

构建完成后，请把上表状态更新为实际结果，并按第 12 节做人工验收；在没有完成真实窗口验收前，不要声称发行产物已经可用。

## 16. 本轮新增项的人工验收

- 确认品牌、默认插画、窄窗和缩放下的可读性；换图、保存、重启、关闭背景、恢复默认。
- 确认公开密码文件是单一明文本：编辑保存、导入追加、清空并重启都不补回默认；重复/空格/`#` 行原样保留（见第 9.3 节步骤与第 12 节第 18–19 项）。
- 选一个已有内容的文件夹当工作文件夹：无关文件保留、不覆盖同名、冲突进入 `_duplicates`，且重启后仍记住该文件夹（见第 12 节第 16、20、21 项）。
- 同一副本分别关闭/开启关键词清理：只有成品顶层名受影响，内部结构与归档原件一致。
- 对照“保留内容原名”开/关，确认成品顶层名的两种命名方式符合预期，且深层包装目录被合理压缩。
- 使用副本核对 ZIP/AES ZIP、7z、RAR、完整分卷、缺卷、错密码和嵌套；对照 [格式矩阵](desktop-format-support.md)，不以某工具支持格式推断项目整体支持。
- ESC、遮罩、保存、关闭后重新打开设置，未提交的密码文本应按“重新载入”行为回到文件内容；结束边界的取消提示应准确。
