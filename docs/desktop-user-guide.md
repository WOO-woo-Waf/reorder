# 归序 · ReOrder 桌面版用户指南（Windows）

本指南面向两类人：拿到安装包或便携包后要实际操作 Windows 桌面版的用户，以及负责最终验收这些操作的验收人。它讲清楚文件怎么放、界面每个按钮做什么、结果落在哪里，以及用真实文件验收时应该看到什么。

相关文档：产品范围见 [product_plan.md](product_plan.md)，工程设计见 [desktop-design.md](desktop-design.md)，实施进度与检查证据见 [desktop-status.md](desktop-status.md)。旧的命令行便携版见 [portable_user_guide.md](portable_user_guide.md)，那是另一个入口，不要与本桌面版混用。

## 0. 交付范围与验收边界

本指南对应 Windows x64 桌面首版预览。当前构建是否成功、Git 提交和检查记录统一见 [desktop-status.md](desktop-status.md)；本指南介绍运行方法。真实文件、操作体验与干净机器安装仍由用户按第 12 节人工验收。

| 项目 | 交付入口 | 说明 |
| --- | --- | --- |
| 桌面源码 | `apps/desktop`、`src/reorder_engine` | 已批准技术栈；保留 CLI |
| Python 冻结引擎 | `engine/reorder-engine.exe` | 必须保留完整 `_internal` 与工具目录 |
| 桌面 EXE | `ReOrder.exe` | 使用系统 WebView2 |
| NSIS 安装包 | `ReOrder_0.2.0_x64-setup.exe` | 用户级安装，尚未签名 |
| 便携 ZIP | `ReOrder-0.2.0-windows-x64.zip` | 解压整个目录；完整性看 `SHA256SUMS.txt` |
| 真实窗口、文件、安装卸载 | 用户人工验收 | 合成引擎检查和源码检查不能替代这一项 |

请按本指南第 12 节用**副本样本**开始人工验收；不要把实现完成等同于真实业务验收通过。

## 1. 系统要求

- Windows 10 或 Windows 11，**x64**。当前只配置了 x64 目标。
- **WebView2 Runtime**（界面渲染依赖它，见下）。
- 足够磁盘空间：处理时会先在内部工作区准备副本，再发布成品并归档原件。单包大概需要“原件总大小 × 2 以上”的临时空间，另外还要留出成品空间。
- 你**不需要**自己安装 Python、Node.js、Rust、7-Zip、WinRAR 或 Bandizip。界面引擎、Python 业务引擎和 7-Zip 都随包提供；UnRAR / Bandizip 是可选的，只有在处理对应格式时才需要。

### 关于 WebView2

桌面界面用系统自带的 WebView2 渲染，这是 Windows 上的运行时组件：

- Windows 11 已经把 Evergreen WebView2 Runtime 作为操作系统的一部分内置。
- Windows 10 上它**不一定**已经安装：很多装有 WebView2 应用（例如新版 Edge/Office）的机器会有，但没有的机器需要补上。
- 本项目当前的 Tauri 配置没有显式设置 `webviewInstallMode`，因此走 Tauri v2 的默认值：NSIS 安装包在运行时会**联网下载并静默安装** WebView2 引导程序；便携 ZIP **不携带** WebView2。所以离线安装、或目标机器没有 Evergreen Runtime 时，需要你提前装好运行时。

如果不确定机器上有没有，可以打开“设置 → 应用 → 已安装的应用”，查找 “Microsoft Edge WebView2 Runtime”。参考链接见第 14 节。

## 2. 你会拿到什么（产物形态与文件树）

发行产物有两种形态；拿到后按下列结构核对完整目录。

### 2.1 便携包（ZIP 解压即用）

解压后目录（由 `scripts\build_desktop_windows.ps1` 生成到 `artifacts\desktop\ReOrder-portable\`，再压成 `ReOrder-0.2.0-windows-x64.zip`）：

```text
ReOrder-portable\
  ReOrder.exe              # 桌面主程序，双击运行
  Start-Portable.cmd       # 显式便携模式：数据在旁边 data/，密码仅会话保存
  README.txt
  package-manifest.json    # 包内文件大小和 SHA-256
  docs\                    # 用户、代码、语言、设计指南及图表
  licenses\                # 第三方许可文本与证据清单
  engine\                  # Python 业务引擎，必须与 ReOrder.exe 一起保留
    reorder-engine.exe
    _internal\             # 引擎运行时依赖
    tools\
      7zip\                # 随包 7-Zip（含 License.txt）
        ...
      apate.py
```

注意：

- **不要只把 `ReOrder.exe` 拷走单独运行**。必须保留整个 `engine\` 目录，里面是处理压缩包所需的真实引擎和 7-Zip。
- 双击 `ReOrder.exe` 使用默认用户数据目录；双击 `Start-Portable.cmd`（等价于 `ReOrder.exe --portable`）使用 EXE 旁的 `data\`，该目录必须可写，密码只保存在当前会话。两者都需要系统 WebView2。

### 2.2 安装包（NSIS）

由 `npm run tauri build` 生成，位置：

```text
apps\desktop\src-tauri\target\release\bundle\nsis\ReOrder_0.2.0_x64-setup.exe
```

- 安装模式为 `currentUser`（当前用户安装，不需要管理员）。
- 安装语言可选简体中文 / English。
- 安装包会把引擎资源安装到程序资源目录；如果机器缺少 WebView2，安装过程会尝试联网获取运行时。

## 3. 启动与界面总览

双击 `ReOrder.exe`、`Start-Portable.cmd`，或从开始菜单启动安装版。窗口标题是“归序 · ReOrder”，最小尺寸 860×620。

界面从上到下是：

1. 顶部标题栏：产品名、副标题“恢复、解压、归档，一次理顺。”，右侧“设置”按钮（未就绪或任务进行中时不可点）。
2. 概览卡片：待处理文件组数量、处理模式（“深度解压”或“单层解压”，由设置决定）、原包归档提示“校验后移动”。
3. **01 添加文件**：拖放区、添加按钮、结果目录。
4. **02 确认并处理 / 处理结果**：扫描/开始/取消/重试按钮、进度条、文件组状态表、处理记录。
5. 最近任务：本机保存的历史列表。
6. 底部状态栏：平台与版本（如 `Windows · v0.2.0`）、7-Zip 是否就绪、当前密码数量。

> 界面所有处理都在本机完成，不联网处理你的文件。唯一可能的联网动作，是安装包在缺少 WebView2 时下载运行时组件。

## 4. 主流程：添加 → 扫描 → 开始 → 取消

### 4.1 添加文件（01 添加文件）

三种方式：

- 点“添加文件”，在系统对话框里多选文件。
- 点“添加文件夹”，选择一个目录（是否包含子目录由设置里的“扫描输入的子目录”决定）。
- 直接把文件或文件夹**拖进窗口**。

规则：

- 请你先只用**副本样本**：把要试的文件复制一份到专门的试验目录，输入指向副本，不要第一次就指向唯一的原始资料（见第 11 节）。
- 明确选中文件时，只处理你所选文件组成的完整分卷组，不动旁边的文件；选中目录时会扫描目录内容。
- 已添加的条目可以“移除”。
- 输入和输出路径都不接受符号链接/连接点（Windows 上的 junction 也会被拒绝）。

**结果目录**：点“选择”指定成品与原包的落点。要求：

- 必须是绝对路径的目录。
- 不能落在软件安装目录或软件内部数据目录里。
- 与输入目录相互独立会更安全，便于你事后区分。

界面提示：“完成后，成品放入 `final`，原包移动到 `success\archives`。失败和缺卷会单独分类；同名文件不会覆盖。”

### 4.2 扫描（只读预览）

添加好输入并选好结果目录后，点“扫描”。这一步是**只读的**：

- 引擎按“文件组”识别分卷、伪装后缀、合并文件（PDF/图片/媒体前缀 + 尾部压缩包）等，给出分组预览：每个文件组的名称、成员数、总大小。
- 扫描不会移动、不会改写你的文件。
- 可能出现警告文字，例如“已扫描子目录；原件按文件组归档，不会预先展平输入”“处理完成后原包会移动到输出目录的归档或错误分类，处理前不会改写原件”。
- 若扫描后你改了输入、输出或设置，需要重新扫描。

### 4.3 开始处理

确认分组后点“开始处理”。过程分几个阶段，界面状态会依次显示：准备副本 → 恢复 / 解压 → 发布成品 → 归档原包。

每个包的底层顺序是：复核原件 → 复制到内部工作区 → 在工作副本上恢复/解压 → 校验后发布成品 → 校验复制结果后删除原件并把原件路由到归档或分类目录。**原件不会原地改写**，但它会在成功后被移动到输出目录（这点很重要，先用副本试）。

### 4.4 取消与关闭窗口

- 任务进行中点“取消”，按钮变为“正在取消”。取消是在**安全边界**生效：当前正在提交的那一步会做完，避免留下半删的原件；尚未开始的包标记为“已取消”，原件留在原处。
- 任务进行中直接关窗口，会弹出确认：“任务仍在处理。取消后请等待文件安全收尾，再关闭软件。”可选择“取消任务”或“继续处理”。
- 退出软件时，宿主会让引擎先收尾当前文件提交；超时后用进程树终止兜底。

## 5. 结果与分类

处理完成后，结果目录下会按类别出现以下目录（取决于每个包的结果）：

| 目录 | 含义 |
| --- | --- |
| `final\` | 完全成功或部分成功时解出/恢复出的成品，优先看这里 |
| `success\archives\` | 成功处理后的原始压缩包（原件归档位） |
| `error_files\<类别>\` | 失败原件，按失败类别分目录 |
| `deferred_volumes\<文件组>\` | 缺少分卷、暂缓处理的文件组 |
| `_duplicates\` | 同名冲突时的隔离目录，防止覆盖已有文件 |

`error_files\` 下的类别名：

- `password_error`：密码不对或加密无法解开。
- `unknown_type`：引擎无法识别类型。
- `missing_volume`：缺分卷。
- `extract_failed`：其它解压失败。

文件组状态的含义（界面里会显示这些中文名）：

| 状态 | 界面文字 | 含义 |
| --- | --- | --- |
| `succeeded` | 完成 | 全部成功 |
| `partial` | 部分完成 | 有成品，但存在缺卷等未完成部分 |
| `failed` | 失败 | 该组处理失败 |
| `deferred` | 等待补卷 | 缺分卷，暂缓，原件放到 `deferred_volumes` |
| `cancelled` | 已取消 | 因取消未处理，原件保留 |
| `interrupted` | 已中断 | 引擎异常退出导致中断 |
| `needs_review` | 需要检查 | 发布或归档无法确定是否完成，需要人工核对，**不会自动重跑** |

结果表里“说明”列会给出错误码或简短说明；日志已脱敏，密码不会出现在里面。

## 6. 打开结果目录

任务卡片右上角“打开结果目录”会调用系统文件管理器打开已登记的路径。出于安全，它只允许打开**引擎登记过**的结果路径，不会打开任意路径。

## 7. 重试

任务结束后，“开始处理”位置会换成“重试 (N)”，N 是可重试的文件组数量。

- 可重试的状态：失败、等待补卷、已取消、已中断。
- 已完成或“需要检查”的包**不会**被重做；“需要检查”的包请你先人工核对后再决定。
- 重试会创建一个新任务，并保留与旧任务的关联；旧的成功包不会重跑。
- 已经路由到错误分类的原件，会被当作重试输入读回。

## 8. 最近任务（历史）

- 历史保存在本机 SQLite（默认 `%LOCALAPPDATA%\io.reorder.desktop\jobs.sqlite3`；显式便携模式为 EXE 旁 `data\jobs.sqlite3`），列出最近 20 条任务及状态。
- 点某条历史会载入该任务的快照与结果表；进行中的任务进行时不能切换查看。
- “刷新”重新读取列表。

## 9. 设置

点右上角“设置”。设置保存在本机，修改后需要重新扫描文件才生效。

### 9.1 处理选项

| 选项 | 默认 | 说明 |
| --- | --- | --- |
| 继续解开嵌套压缩包（深度解压） | 开 | 关闭时只解一层 |
| 扫描输入的子目录 | 关 | 开启后递归扫描输入的目录 |
| 保留内容原名 | 开 | 保留解出内容的原始名称 |
| 保留临时工作区 | 关 | 开启后不自动删除中间工作目录，便于排错 |
| 最大解压层数 | 4 | 1–20 |
| 输出空间上限 (GB) | 64 | 成品空间上限 |
| 工具超时 (秒) | 3600 | 单次外部工具调用上限，1–86400 |
| 嵌套归档识别下限 (MB) | 100 | 小于该大小的文件不做深挖 |
| 单文件成品阈值 (MB) | 200 | 大文件回退阈值 |

### 9.2 解压工具

- **7-Zip（必需）**：默认自动查找。便携包会自带 7-Zip；如果没找到，界面底部会提示“在设置中检查 7-Zip”。可用“选择”手动指定本机的 `7z.exe` / `7zz`。
- **UnRAR（可选）**、**Bandizip（可选）**：仅有对应格式需求时才需要，可留空。

### 9.3 密码集与凭据后端

密码用于解开加密压缩包。支持三种方式更新：

- 在设置的多行框里直接粘贴，每行一个密码，点“替换密码集”（会整体替换现有密码集）。
- “导入密码文件”：选择一个 UTF-8 编码的 `.txt`（不超过 512 KiB），每行一个密码。
- “清空”移除全部密码。

存储模式（设置里会显示）：

- **系统凭据保存**：通过 Windows 凭据管理（keyring）保存，重开软件仍在。
- **仅本次会话保存**：系统凭据后端不可用时退回内存保存，退出软件后需要重新导入；不会明文落盘。

安全说明：软件只允许使用系统凭据后端，不会把密码写进普通文件；日志和错误信息里的密码会被替换为“[密码已隐藏]”；界面只显示密码**数量**，不显示明文。

## 10. 用户数据与状态位置

Windows 上用户数据根目录是：

```text
%LOCALAPPDATA%\io.reorder.desktop\
```

其中：

| 路径 | 内容 |
| --- | --- |
| `settings.json` | 你保存的设置 |
| `jobs.sqlite3` | 任务/文件组/事件/动作日志（历史） |
| `work\` | 处理工作区（保留工作区开启时才留下内容） |
| `logs\` | 每个任务的脱敏日志（单任务约 2 MiB 滚动） |
| `engine-diagnostics.log` | 引擎诊断输出（约 2 MiB 滚动） |
| `engine.lock` | 单实例锁 |

软件安装目录里不放用户数据；输出目录与用户数据目录相互独立。

## 11. 只用副本样本开始（入门演练）

第一次上手请按这个顺序，全程只碰副本：

1. 新建一个试验目录，例如 `D:\reorder-trial\input`，把**要试的压缩包的副本**放进去（几个分卷要放齐，并保持原始文件名）。
2. 新建输出目录 `D:\reorder-trial\output`。
3. 打开软件，添加输入（拖入或“添加文件夹”），把结果目录设为 output。
4. 点“扫描”，确认文件组数量、名称、成员数和大小符合预期。
5. 点“开始处理”，观察状态从“准备副本”走到“完成”。
6. 处理结束后核对：output 下的 `final\` 是否有内容、`success\archives\` 是否是被移动过来的原件。
7. 确认无误后，再考虑用真实文件。

## 12. 真实文件人工验收清单

下列各项需要在一台真实 Windows 机器上，用你自己的文件（先副本、后少量真实样本）逐条操作并记录结果。**这些项目目前都还没有做过，属于待人工验收**；请如实记录“通过 / 失败 / 未做”。

| # | 操作 | 预期结果 | 记录 |
| --- | --- | --- | --- |
| 1 | 干净或半干净的 Windows 10 机器上安装 NSIS 包并在缺 WebView2 时联网 | 安装成功，启动后能显示界面；若离线且无 WebView2，则应报出可理解的运行时缺失提示 | |
| 2 | 便携包解压后双击 `ReOrder.exe` | 界面正常打开，底部显示平台与版本，7-Zip 显示“已就绪” | |
| 3 | 只拷贝 `ReOrder.exe`、删掉 `engine\` 后启动 | 明确提示引擎资源缺失，而不是静默失败 | |
| 4 | 添加一个普通 ZIP，扫描 | 分组预览正确，成员数与大小正确 | |
| 5 | 添加一组分卷（如 `.7z.001/.002`），扫描并处理 | 归为同一组，成功解出，原件进入 `success\archives\` | |
| 6 | 添加伪装后缀/合并文件（前缀 + 尾部压缩包）样本 | 能恢复并解出，成品在 `final\` | |
| 7 | 添加一个加密 ZIP，先在设置里加入正确密码 | 能解开；密码数量正确；日志中看不到明文密码 | |
| 8 | 用错误密码解加密包 | 该组失败并归入 `error_files\password_error\`，提示可理解 | |
| 9 | 加入缺分卷的组 | 该组为“等待补卷”，原件进入 `deferred_volumes\<组>\` | |
| 10 | 处理一个较大的组，中途点“取消” | 状态先“正在取消”后“已取消”；未开始的组原件保留；不产生半成品假成功 | |
| 11 | 任务进行中关窗口 | 弹出确认；选择取消后文件安全收尾再关闭 | |
| 12 | 对失败或已取消的组点“重试” | 生成新任务并保留与旧任务的关联；成功包不重跑 | |
| 13 | 查看“最近任务”，点历史条目 | 能载入历史快照与结果；进行中任务不能切换 | |
| 14 | 点“打开结果目录” | 打开的是引擎登记过的结果路径 | |
| 15 | 在安装目录/用户数据目录内选结果目录 | 被拒绝并给出提示 | |
| 16 | 关闭“保留临时工作区”，成功处理后检查默认数据目录或便携 `data\work\` | 成功工作副本被清理；中断/未决动作保留供人工检查 | |
| 17 | 卸载安装版 | 程序卸载干净；用户数据目录按预期保留或删除（记录实际行为） | |

记录时请写清：样本类型、文件大小、机器 Windows 版本与 WebView2 状态、实际输出路径、是否与预期一致。真实特殊格式的最终效果由你人工判定，这属于业务验收，不能用合成样本的机器检查代替。

## 13. 常见问题

- **启动时报引擎资源缺失**：便携包没解压完整，或 `engine\` 目录被移动。保留整个目录重试。
- **界面打不开或白屏**：多半是 WebView2 缺失。安装 Evergreen WebView2 Runtime 后重试。
- **底部提示“在设置中检查 7-Zip”**：设置里指定 7z 路径，或用便携包自带 7-Zip。
- **输入或输出被拒绝**：路径含符号链接/连接点、不是绝对路径、或落在安装目录/数据目录内。
- **扫描后提示设置已改变**：改动设置后需要重新扫描。
- **组显示“需要检查”**：发布或归档无法确定是否完成，请人工核对结果目录与动作日志，不会自动重跑。
- **同名文件被挪进 `_duplicates`**：软件不覆盖已有文件，把冲突项隔离到那里。

  ```powershell
  D:\buff\reorder\runtime\desktop-build-venv\Scripts\python.exe .\scripts\stage_desktop_engine.py
  ```

  ```cmd
  runtime\check-desktop.cmd
  ```
